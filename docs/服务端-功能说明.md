# 服务端功能说明

服务端没有给买家点的页面。它是一直开着的程序：用户端和管理端把「登录、发起合同、签署、认证、支付」这些请求发给它，它检查是否允许、把结果存进数据库，必要时再去问微信、支付宝、短信这些外面的服务。

## 它管什么数据

数据库脚本在仓库根目录 `db/dianzihetong.sql`。开发库名是 `dianzihetong`。合同、企业、印章、用户、菜单权限、套餐等都记在这里。

开源 SQL 已带：

- 全部表结构
- `sys_menu` / `sys_role` / `sys_role_menu`（管理端菜单与权限）
- 演示管理员 `admin` / `admin123`
- 已清空密钥后的 `common_info`、`sys_config` 配置项骨架

不含真实用户合同、企业认证材料等业务数据。

## 主要能力（按业务）

### 账号与权限

- **用户端注册 / 登录**：手机号 + 短信验证码，或密码 / 微信授权。通过后发 JWT。
- **管理端登录**：账号密码 + 图形验证码；菜单与按钮权限来自 `sys_menu` 与角色关联。
- **个人 / 企业认证**：提交资料，管理端审核或按配置走自动审核。

### 合同

- **发起合同**：选模板或上传文件，填写字段，指定签署方与抄送方。
- **签署 / 拒签 / 撤销**：记录签署状态；到期未签可按配置过期。
- **模板与类型**：合同模板、字段、合同类型维护。
- **文档处理**：Word / 图片等转 PDF、盖章合成（依赖 LibreOffice 等本地工具或线上转换配置）。

### 企业与印章

- **企业空间**：企业认证、成员关系。
- **印章**：个人章 / 企业章的创建与合同盖章使用。

### 交易与会员

- **签署套餐 / 会员**：下单、微信支付 / 支付宝；支付回调后改订单与次数。
- **财务流水、提现申请**：管理端审核；自动打款需自行接支付侧能力。

### 消息与配置

- **站内消息 / 短信提醒**：签署通知、认证结果等。
- **系统配置**：短信、微信、支付宝、OSS、客服、协议文案等，多写在 `common_info`。

## 代码大致在哪

| 包路径 | 做什么 |
|---|---|
| `com.sqx.modules.contract` | 合同、模板、签署相关 |
| `com.sqx.modules.enterprise` | 企业认证与企业用户 |
| `com.sqx.modules.app` | 用户端账号、认证等接口 |
| `com.sqx.modules.pay` | 支付、回调 |
| `com.sqx.modules.oss` | 文件上传与云存储 |
| `com.sqx.modules.sys` | 管理端用户、角色、菜单 |

## 外面的服务怎么接

密钥都填在管理端配置页（入库），不要写死在前端。

### 短信

注册、改密、签署提醒等会发短信。

- 腾讯云短信：https://cloud.tencent.com/product/sms
- 阿里云短信：https://www.aliyun.com/product/sms

### 微信支付 / 支付宝

购买套餐等场景：服务端向支付侧下单，用户端拉起支付，支付成功回调后再改订单。

- 微信：https://pay.weixin.qq.com/ 、小程序 / 公众号 AppId：https://mp.weixin.qq.com/
- 支付宝：https://open.alipay.com/

### 对象存储

头像、合同文件、印章图等。开源默认偏向本地上传；要上云再配 OSS / COS。

- 阿里云 OSS：https://www.aliyun.com/product/oss

### 企业信息查询（可选）

企业认证时查询工商信息，对应 `common_info` 里企业查询相关配置项，需自行申请云市场 / API。

## 和另外两端的关系

用户端和管理端都不直接写合同主数据。它们把请求发给服务端，服务端再决定要不要去问微信、短信或图床。

- 默认端口 **9131**，上下文路径 **`/sqx_fast`**。
- 外面的密钥只配在服务端能读到的配置里。只在用户端页面上改文字，不会变成已经开通了微信支付。
